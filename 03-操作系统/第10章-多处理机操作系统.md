# 第10章 多处理机操作系统

## 10.1 多处理机系统的基本概念
### 10.1.1 多处理机系统的引入
**多处理机系统**是指包含多个中央处理器（CPU）的计算机系统。

**引入多处理机系统的原因**：
- **提高性能**：多个CPU可以并行处理任务
- **提高可靠性**：一个CPU故障不会导致整个系统崩溃
- **提高吞吐量**：同时处理多个任务
- **支持复杂应用**：如科学计算、大数据处理等

**多处理机系统与并行处理**：
- **并行处理**：同时执行多个任务
- **并发处理**：多个任务交替执行

### 10.1.2 多处理机系统的类型
**按耦合程度分类**：
- **紧密耦合系统**：多个CPU共享内存和I/O设备
- **松散耦合系统**：多个CPU有各自的内存和I/O设备，通过网络连接

**按处理机类型分类**：
- **同构多处理机系统**：所有CPU类型相同
- **异构多处理机系统**：CPU类型不同，各司其职

**按内存访问方式分类**：
- **UMA（统一内存访问）系统**：所有CPU访问内存的速度相同
- **NUMA（非统一内存访问）系统**：CPU访问本地内存的速度比访问远程内存快
- **COMA（缓存一致性内存访问）系统**：所有内存都是缓存

## 10.2 多处理机系统的结构
### 10.2.1 统一内存访问多处理机系统结构
**UMA系统**：所有CPU共享一个物理内存，访问内存的时间相同。

**结构**：
- 多个CPU通过总线连接到共享内存
- 共享I/O设备
- 总线是系统的瓶颈

**优点**：
- 结构简单
- 编程容易
- 内存一致性容易保证

**缺点**：
- 总线瓶颈限制系统规模
- 可扩展性差

### 10.2.2 非统一内存访问多处理机系统结构
**NUMA系统**：每个CPU有本地内存，访问本地内存的速度比访问远程内存快。

**结构**：
- 多个节点，每个节点包含CPU和本地内存
- 节点之间通过高速互连网络连接
- 每个节点可以访问其他节点的内存

**优点**：
- 可扩展性好
- 减少总线瓶颈
- 适合大规模系统

**缺点**：
- 编程复杂
- 内存访问时间不一致
- 需要特殊的内存管理策略

## 10.3 多处理机操作系统的特征与类型
### 10.3.1 多处理机操作系统的特征
**多处理机操作系统**是管理多处理机系统的操作系统。

**特征**：
- **并行性**：支持多个CPU并行执行任务
- **分布性**：管理分布的资源
- **容错性**：处理CPU故障
- **可扩展性**：支持系统规模的扩展

### 10.3.2 多处理机操作系统的功能
**功能**：
- **进程管理**：支持多进程并行执行
- **内存管理**：管理共享内存和分布内存
- **资源管理**：分配和管理系统资源
- **进程同步**：协调多个进程的执行
- **进程通信**：支持进程间通信
- **负载均衡**：平衡各CPU的负载

### 10.3.3 多处理机操作系统的类型
**类型**：
- **主从式操作系统**：一个CPU作为主处理器，其他作为从处理器
- **对称式操作系统**：所有CPU地位平等，共享操作系统
- **分布式操作系统**：每个节点有自己的操作系统，通过网络协调

**主从式操作系统**：
- **优点**：实现简单，开销小
- **缺点**：主处理器容易成为瓶颈，可靠性低

**对称式操作系统**：
- **优点**：负载均衡好，可靠性高
- **缺点**：实现复杂，开销大

## 10.4 多处理机操作系统的进程同步
### 10.4.1 集中式同步方式与分布式同步方式
**进程同步**是指协调多个进程的执行，确保它们按照正确的顺序访问共享资源。

**集中式同步**：
- 由一个中央协调器负责同步
- 实现简单
- 中央协调器可能成为瓶颈

**分布式同步**：
- 没有中央协调器，进程之间直接协调
- 可扩展性好
- 实现复杂

### 10.4.2 自旋锁
**自旋锁**是一种忙等待的锁，进程会一直循环检查锁是否可用。

**优点**：
- 适用于短时间的临界区
- 没有上下文切换的开销

**缺点**：
- 浪费CPU时间
- 可能导致活锁

**实现**：
```
spin_lock(lock) {
    while (!test_and_set(lock));
}

spin_unlock(lock) {
    lock = 0;
}
```

### 10.4.3 读-复制-更新锁
**读-复制-更新（RCU）锁**是一种用于读多写少场景的同步机制。

**原理**：
- 读操作不需要加锁
- 写操作创建数据的副本，修改后再替换
- 等待所有读操作完成后释放旧数据

**优点**：
- 读操作性能高
- 适用于读多写少的场景

**缺点**：
- 写操作开销大
- 实现复杂

### 10.4.4 二进制指数补偿算法和待锁CPU等待队列机构
**二进制指数补偿算法**：当进程获取锁失败时，等待时间呈指数增长。

**优点**：
- 减少锁竞争
- 提高系统吞吐量

**待锁CPU等待队列机构**：将等待锁的进程组织成队列，按顺序获取锁。

**优点**：
- 保证公平性
- 减少忙等待

### 10.4.5 定序机构
**定序机构**是指确保操作按照一定的顺序执行。

**方法**：
- **时间戳**：为每个操作分配时间戳，按时间戳顺序执行
- **全局计数器**：使用全局计数器为操作编号

### 10.4.6 面包房算法
**面包房算法**是一种分布式互斥算法，确保进程按顺序进入临界区。

**原理**：
- 进程进入面包房时取一个号码
- 按号码顺序进入临界区
- 离开时释放号码

**优点**：
- 公平性好
- 不需要硬件支持

**缺点**：
- 实现复杂
- 开销较大

### 10.4.7 令牌环算法
**令牌环算法**是一种分布式互斥算法，通过令牌来控制对临界区的访问。

**原理**：
- 令牌在进程之间循环传递
- 只有持有令牌的进程可以进入临界区
- 进入临界区后释放令牌

**优点**：
- 公平性好
- 适用于分布式系统

**缺点**：
- 令牌丢失会导致系统故障
- 令牌传递开销较大

## 10.5 多处理机操作系统的进程调度
### 10.5.1 调度性能的评价因素
**调度性能的评价因素**：
- **CPU利用率**：CPU的使用时间占总时间的比例
- **系统吞吐量**：单位时间内完成的任务数
- **响应时间**：从任务提交到开始执行的时间
- **周转时间**：从任务提交到完成的时间
- **公平性**：任务获得CPU时间的公平程度
- **可扩展性**：系统规模扩大时性能的变化

### 10.5.2 进程分配方式
**进程分配方式**：
- **静态分配**：进程固定分配给某个CPU
- **动态分配**：进程根据负载动态分配给CPU
- **迁移分配**：进程在不同CPU之间迁移

**静态分配**：
- **优点**：减少进程迁移开销，缓存局部性好
- **缺点**：负载可能不均衡

**动态分配**：
- **优点**：负载均衡好
- **缺点**：进程迁移开销大

### 10.5.3 进程（线程）调度方式
**调度方式**：
- **全局调度**：所有CPU共享一个就绪队列
- **局部调度**：每个CPU有自己的就绪队列
- **两级调度**：结合全局和局部调度

**全局调度**：
- **优点**：负载均衡好
- **缺点**：调度开销大，缓存局部性差

**局部调度**：
- **优点**：调度开销小，缓存局部性好
- **缺点**：负载可能不均衡

### 10.5.4 死锁的分类、检测与解除
**死锁**是指多个进程因互相等待资源而陷入的僵持状态。

**多处理机系统中的死锁分类**：
- **资源死锁**：因争夺资源而死锁
- **通信死锁**：因进程间通信而死锁
- **嵌套死锁**：多个层次的死锁

**死锁检测**：
- **集中式检测**：由一个中央进程负责检测
- **分布式检测**：进程之间相互检测

**死锁解除**：
- **资源剥夺**：从死锁进程中剥夺资源
- **进程终止**：终止部分死锁进程
- **进程回滚**：将进程回滚到之前的安全状态
