# 第8章 文件管理

## 8.1 文件和文件系统
### 8.1.1 文件、记录和数据项
**文件**是指由创建者所定义的、具有文件名的一组相关元素的集合。

**记录**是文件中的基本数据单位，由若干个数据项组成。

**数据项**是文件中最小的可访问单位，如一个字符、一个整数等。

**文件的属性**：
- 文件名
- 文件类型
- 文件大小
- 创建时间
- 修改时间
- 访问权限

### 8.1.2 文件名和文件类型
**文件名**是用于标识文件的字符串，通常由主名和扩展名组成。

**文件类型**：
- **普通文件**：包含用户数据
- **目录文件**：包含其他文件的目录项
- **特殊文件**：表示设备

**常见的文件扩展名**：
- `.txt`：文本文件
- `.doc`：Word文档
- `.jpg`：图片文件
- `.exe`：可执行文件

### 8.1.3 文件系统的层次结构
**文件系统**是操作系统中负责管理文件的部分。

**文件系统的层次结构**：
1. **用户接口层**：提供用户操作文件的接口
2. **文件目录系统**：管理文件目录
3. **文件存储管理**：管理文件的存储
4. **I/O控制层**：处理文件的I/O操作

**常见的文件系统**：
- FAT32
- NTFS
- ext4
- HFS+

## 8.2 文件的逻辑结构
### 8.2.1 文件逻辑结构的类型
**文件的逻辑结构**是指文件在用户眼中的组织形式。

**类型**：
- **顺序文件**：文件中的记录按顺序排列
- **索引文件**：通过索引表来组织文件
- **索引顺序文件**：结合顺序文件和索引文件的优点
- **直接文件**：通过哈希函数直接访问文件

### 8.2.2 顺序文件
**顺序文件**是指文件中的记录按顺序排列，顺序访问。

**类型**：
- **连续顺序文件**：记录在物理上连续存储
- **串联顺序文件**：记录通过指针链接

**优点**：
- 顺序访问效率高
- 实现简单

**缺点**：
- 随机访问效率低
- 插入和删除操作复杂

### 8.2.3 索引文件
**索引文件**是指通过索引表来组织文件，索引表记录每个记录的位置。

**优点**：
- 随机访问效率高
- 插入和删除操作方便

**缺点**：
- 需要额外的索引空间
- 索引表的维护开销

### 8.2.4 索引顺序文件
**索引顺序文件**是指将文件分为若干个块，每个块有一个索引项。

**优点**：
- 结合了顺序文件和索引文件的优点
- 随机访问和顺序访问效率都较高

### 8.2.5 直接文件和哈希文件
**直接文件**是指通过关键字直接访问文件。

**哈希文件**是指使用哈希函数将关键字映射到文件地址。

**优点**：
- 访问速度快
- 适用于按键值查找

**缺点**：
- 可能产生哈希冲突
- 不支持范围查询

## 8.3 文件目录
### 8.3.1 文件控制块和索引节点
**文件控制块（FCB）**是文件的描述信息，包含文件的属性和位置。

**索引节点（inode）**是文件系统中用于存储文件属性和位置信息的数据结构。

**索引节点的内容**：
- 文件类型
- 文件权限
- 文件大小
- 创建时间
- 修改时间
- 访问时间
- 文件数据的位置

### 8.3.2 简单的文件目录
**简单的文件目录**是指一个目录文件，包含所有文件的FCB。

**优点**：
- 实现简单

**缺点**：
- 查找效率低
- 不支持文件重名
- 不支持目录层次

### 8.3.3 树形目录
**树形目录**是指目录结构呈树状，有一个根目录，下面有多个子目录。

**优点**：
- 支持文件重名
- 支持目录层次
- 查找效率高

**路径**：
- **绝对路径**：从根目录开始的路径
- **相对路径**：从当前目录开始的路径

```mermaid
graph TD
    ROOT[/] --> home[home]
    ROOT --> usr[usr]
    ROOT --> etc[etc]
    home --> user[user]
    user --> a[a.txt]
    user --> b[b.txt]
    usr --> bin[bin]
    usr --> lib[lib]
    style ROOT fill:#f96,stroke:#333,stroke-width:3px
    style user fill:#bbf
    style a fill:#dfd
    style b fill:#dfd
```

### 8.3.4 无环图目录
**无环图目录**是指目录结构中存在共享文件，通过链接实现。

**优点**：
- 支持文件共享
- 节省存储空间

**缺点**：
- 可能导致循环引用
- 目录管理复杂

### 8.3.5 目录查询技术
**目录查询技术**是指查找文件的方法。

**方法**：
- **线性搜索**：逐个查找目录项
- **哈希查找**：使用哈希函数快速定位
- **B树查找**：使用B树结构提高查找效率

## 8.4 文件共享
### 8.4.1 利用有向无环图实现文件共享
**有向无环图（DAG）**是指通过指针共享文件，避免循环引用。

**优点**：
- 实现文件共享
- 节省存储空间

**缺点**：
- 目录管理复杂
- 可能导致悬挂指针

### 8.4.2 利用符号链接实现文件共享
**符号链接**是指创建一个特殊的文件，指向另一个文件的路径。

**优点**：
- 实现文件共享
- 可以跨文件系统
- 不会导致循环引用

**缺点**：
- 需要额外的存储空间
- 可能导致链接失效

## 8.5 文件保护
### 8.5.1 保护域
**保护域**是指用户或进程可以访问的资源集合。

**目的**：
- 防止未授权的访问
- 保护文件的安全性

### 8.5.2 访问矩阵的概念
**访问矩阵**是指一个二维矩阵，行表示主体（用户或进程），列表示客体（文件或资源），元素表示主体对客体的访问权限。

**访问权限**：
- 读（R）
- 写（W）
- 执行（X）
- 删除（D）
- 创建（C）

### 8.5.3 访问矩阵的修改
**访问矩阵的修改**是指改变主体对客体的访问权限。

**修改方式**：
- **授权**：增加访问权限
- **撤销**：减少访问权限
- **转让**：将访问权限转让给其他主体

### 8.5.4 访问矩阵的实现
**访问矩阵的实现**：
- **访问控制列表（ACL）**：为每个客体维护一个访问控制列表
- **能力表**：为每个主体维护一个能力表
- **权限位**：使用位掩码表示访问权限

## 8.6 文件的物理结构 ⭐⭐⭐

> 文件在磁盘上怎样存放？

### 连续分配

文件数据存储在磁盘的连续块中。

| 优点 | 缺点 |
|------|------|
| 顺序访问快、实现简单 | 有**外部碎片**、文件大小难预估、扩展困难 |

### 链接分配

每块指向下一块，不要求连续。

| 方式 | 说明 | 问题 |
|------|------|------|
| **隐式链接** | 块内指针指向下一块 | 只适合顺序访问 |
| **显式链接** | **FAT表**记录链接关系 | 需要FAT表 |

> [!tip] FAT（文件分配表）
> Windows常用的方式。FAT表在磁盘中有一张表，记录每个块的下一块地址。FAT的表项数决定最大分区大小（如FAT16最大2^16个簇）。

### 索引分配 ⭐

每个文件有一张索引块，记录所有数据块的地址。

```
文件 → [索引块] → [B0][B1][B2][B3]...
```

| 方案 | 文件大小上限 |
|------|-------------|
| **单级索引** | 索引块大小决定 |
| **多级索引** | 指数级增长 |
| **混合索引** | 小文件直接、大文件间接（高效） |

### Unix混合索引分配 ⭐⭐

i-node中提供多个地址项：直接地址 + 间接地址。

```mermaid
graph TD
    INODE[i-node] --> D0[直接指针0]
    INODE --> D1[直接指针1]
    INODE --> D9[直接指针9]
    INODE --> I1[一级间接指针]
    INODE --> I2[二级间接指针]
    INODE --> I3[三级间接指针]
    D0 --> B0[(数据块0)]
    D1 --> B1[(数据块1)]
    D9 --> B9[(数据块9)]
    I1 --> B10[(数据块10)]
    I1 --> Bn[(...)]
    I2 --> B100[(数据块100)]
    I2 --> Bon[...]
    I3 --> B1000[(数据块1000)]
    style INODE fill:#f9f
    style D0 fill:#dfd
    style D9 fill:#dfd
    style I1 fill:#bbf
    style I2 fill:#bbf
    style I3 fill:#f66
```


> 小文件不浪费索引空间，大文件通过多级间接扩展，兼顾了速度和空间。

## 8.7 空闲空间管理 ⭐⭐

| 方法 | 原理 | 优点/缺点 |
|------|------|-----------|
| **空闲表法** | 记录空闲块起始+长度 | 适合连续分配 |
| **位图法** | 0/1位图表示块占用 | **简单常用** |
| **空闲链表法** | 空闲块链接起来 | 分配回收简单 |
| **成组链接法** | Unix方式，分组管理 | 兼顾速度和空间 |

## 8.8 目录查询

### 文件控制块（FCB）与索引节点（inode）

| 概念 | 说明 |
|------|------|
| **FCB（文件控制块）** | 文件描述信息，包含文件属性和位置（与目录项一起存在目录文件中） |
| **inode（索引节点）** | 存储文件属性和位置信息的数据结构（文件名存在目录项，inode单独存放） |

引入inode后，目录文件只存储文件名+inode编号，目录检索显著加快。

### 目录检索平均次数

> FCB占128B，盘块8KB → 每块存8192/128=64个FCB
> 800个目录项 → 800/64≈13块
> 平均检索 = (13+1)/2 = 7次

> [!tip] 公式
> 平均磁盘访问次数 = (目录占用块数 + 1) / 2

## 8.9 本章小结
- 文件物理结构：连续 / 链接（FAT）/ 索引（混合索引）
- 空闲空间管理：空闲表 / 位图 / 空闲链表 / 成组链接
- 目录结构：单级 → 两级 → 树形 → 无环图
- inode 分离目录项与文件属性，大幅减少磁盘访问次数
- 硬链接（共享inode） vs 软链接（路径引用）
