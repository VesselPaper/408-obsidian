# 第4章 进程同步与死锁

## 4.1 进程同步的基本概念
### 4.1.1 进程同步概念的引入
**进程同步**就是协调多个进程的执行顺序，让它们按正确的顺序工作，别出乱子。

**为什么要同步？** 想象一个场景：你和你的室友共用一个银行账户，账户里有1000元。你们同时在不同的ATM机取钱，都要取500元。如果没有同步机制，可能出现这种情况：
1. 你查询余额：1000元
2. 室友查询余额：1000元
3. 你取500元，账户剩500元
4. 室友取500元，账户剩500元

结果你们一共取了1000元，但账户里还剩500元！这就是**竞争条件**——多个进程同时访问共享资源时，由于执行顺序不确定，导致结果错误。

### 4.1.2 临界区问题
**临界区**就是进程中访问共享资源的那段代码。比如上面例子中"查询余额→取钱→更新余额"这段代码就是临界区。

**临界区问题**：怎么保证一次只有一个人能进临界区？

**临界区的三条规则**：
1. **互斥**：一次只能有一个人进临界区（就像厕所，一次只能一个人用）
2. **前进**：如果没人用，等待的人就可以进（厕所没人就可以进）
3. **有限等待**：不能让人无限期等下去（不能让某个人永远进不去厕所）

## 4.2 进程同步机制
### 4.2.1 硬件同步机制
**硬件同步机制**是通过特殊的硬件指令来实现同步。

**常用的硬件指令**：
- **测试并设置指令（Test-and-Set）**：检查一个标志位，如果是0就设为1，整个过程不可打断。就像检查厕所门锁，如果没锁就锁上，整个过程一气呵成
- **交换指令（Swap）**：交换两个值
- **比较并交换指令（Compare-and-Swap）**：比较一个值，如果相等就交换

这些指令的特点是**原子性**——要么全做完，要么不做，不能做到一半被打断。

### 4.2.2 锁机制
**锁**是最简单的同步机制，就像厕所的门锁。

**基本操作**：
- **acquire()**：上锁（进厕所锁门）
- **release()**：解锁（出厕所开门）

**使用流程**：
```
acquire(lock);  // 进门前锁门
// 临界区代码（访问共享资源）
release(lock);  // 出门后开门
```

### 4.2.3 信号量机制
**信号量**是更强大的同步工具，可以理解为"资源计数器"。

**举个例子**：图书馆有5个自习座位，用信号量表示空闲座位数。
- 信号量初始值为5
- 有人进来，信号量减1
- 有人离开，信号量加1
- 信号量为0时，后来的人要等待

**P操作**（等待/占用资源）：
```
P(S) {
    如果 S <= 0，就一直等；
    S = S - 1;  // 占用一个资源
}
```

**V操作**（信号/释放资源）：
```
V(S) {
    S = S + 1;  // 释放一个资源
}
```

**类型**：
- **二元信号量**：只有0和1两个值，相当于锁（厕所要么有人要么没人）
- **计数信号量**：可以是任意非负整数（图书馆的座位数）

### 4.2.4 管程机制
**管程**是更高级的同步机制，把共享资源和操作封装在一起，就像一个"智能厕所管理系统"。

**组成**：
- 共享变量（厕所的使用状态）
- 操作共享变量的过程（进门、出门的方法）
- 条件变量（等待队列）

**特点**：
- 一次只有一个进程可以进入管程
- 提供条件变量让进程等待（比如等厕所空出来）

## 4.3 经典的进程同步问题
### 4.3.1 生产者-消费者问题
**问题描述**：
- 生产者：做面包的师傅
- 消费者：买面包的顾客
- 缓冲区：面包架（只能放10个面包）

**同步需求**：
- 面包架满了，师傅不能再做了（要等顾客买了再做）
- 面包架空了，顾客买不到（要等师傅做了再买）
- 一次只能有一个人动面包架（不能同时放和拿）

**解决方案**：用三个信号量
- `empty`：空位数量（初始10）
- `full`：满位数量（初始0）
- `mutex`：互斥锁（保护面包架）

```
生产者：
    做面包；
    P(empty);  // 等空位
    P(mutex);  // 锁面包架
    放面包；
    V(mutex);  // 解锁
    V(full);   // 满位+1

消费者：
    P(full);   // 等有面包
    P(mutex);  // 锁面包架
    拿面包；
    V(mutex);  // 解锁
    V(empty);  // 空位+1
```

### 4.3.2 哲学家进餐问题
**问题描述**：
5个哲学家围坐圆桌，每人面前一碗饭，每两人之间一根筷子。哲学家要么思考，要么吃饭。吃饭需要两根筷子。

**可能的问题**：
- **死锁**：5个人同时拿起左边的筷子，都等右边的筷子，结果谁都吃不了
- **饥饿**：某个哲学家一直抢不到筷子

**解决方案**：
1. **限制人数**：最多允许4个人同时拿筷子（至少有一人能吃到）
2. **奇偶策略**：奇数号先拿左边，偶数号先拿右边（打破对称）
3. **服务员制度**：拿筷子要经过服务员同意（用管程）

### 4.3.3 读者-写者问题
**问题描述**：
- 读者：只看书的人（可以多人同时看）
- 写者：做笔记的人（必须独占）

**类型**：
- **读者优先**：只要有读者在看，后来的读者可以直接进，写者要等
- **写者优先**：写者来了之后，读者要等

**解决方案**（读者优先）：
```
读者：
    P(mutex);  // 保护读者计数
    read_count++;
    if (read_count == 1) P(rw_mutex);  // 第一个读者锁住写者
    V(mutex);
    
    读书；
    
    P(mutex);
    read_count--;
    if (read_count == 0) V(rw_mutex);  // 最后一个读者释放
    V(mutex);

写者：
    P(rw_mutex);  // 等所有读者离开
    写东西；
    V(rw_mutex);
```

## 4.4 进程同步实例
### 4.4.1 实例1：Linux进程同步
**Linux的同步机制**：
- **互斥锁**：`pthread_mutex_t`（最基本的锁）
- **读写锁**：`pthread_rwlock_t`（区分读者和写者）
- **条件变量**：`pthread_cond_t`（让进程等待某个条件）
- **信号量**：`sem_t`（资源计数）
- **自旋锁**：`spinlock_t`（忙等待的锁）

### 4.4.2 实例2：Windows进程同步
**Windows的同步机制**：
- **互斥量**：`CreateMutex`（类似锁）
- **信号量**：`CreateSemaphore`（资源计数）
- **事件**：`CreateEvent`（通知其他进程某事发生）
- **临界区**：`InitializeCriticalSection`（快速的用户态锁）

## 4.5 死锁
### 4.5.1 死锁描述
**死锁**就是多个进程互相等待对方释放资源，结果谁都动不了。

**生活中的例子**：
- 你拿着剪刀，我拿着胶水，我们要合作做手工
- 你需要胶水，我需要剪刀
- 你等我把胶水给你，我等你把剪刀给我
- 结果谁也干不了活

**死锁的四个必要条件**（缺一不可）：
1. **互斥条件**：资源一次只能被一个进程使用（剪刀只有一把）
2. **请求与保持条件**：拿着资源还要别的资源（拿着剪刀还要胶水）
3. **不剥夺条件**：资源不能被抢走（不能强行把剪刀夺过来）
4. **循环等待条件**：形成等待环（你等我，我等你）

### 4.5.2 死锁预防
**死锁预防**就是破坏上面四个条件中的一个或多个。

**方法**：
- **破坏互斥条件**：让资源可以共享（买两把剪刀）
- **破坏请求与保持条件**：一次性申请所有资源（一开始就把剪刀和胶水都拿来）
- **破坏不剥夺条件**：允许抢资源（可以把剪刀夺过来）
- **破坏循环等待条件**：按顺序申请资源（规定必须先拿剪刀再拿胶水）

### 4.5.3 死锁避免
**死锁避免**是在分配资源前先判断：给了你会不会死锁？只有安全才给。

**安全状态**：存在一种顺序，让所有进程都能完成。

**银行家算法**（像个谨慎的银行家）：
1. 进程申请资源时，先假装分配给它
2. 检查系统是否还处于安全状态
3. 如果安全，真的分配；如果不安全，拒绝分配

**例子**：银行有10万存款，三个客户A、B、C分别需要8万、6万、4万。
- A借了3万，B借了2万，C借了1万，还剩4万
- 这时A要再借3万，银行家会想：给了A，剩1万，不够B或C的最大需求，不安全！
- 所以拒绝A的请求

### 4.5.4 死锁的检测与解除
**死锁检测**：定期检查有没有死锁（像体检一样）。

**死锁解除**（发现死锁后的处理方法）：
- **资源剥夺**：从某些进程抢资源给其他进程（把A的剪刀抢过来给我）
- **进程终止**：杀掉一个或多个死锁进程（让A退出，把资源给其他人）
- **进程回滚**：让进程回到之前的状态（让A回到拿剪刀之前的状态）

## 4.6 本章小结
- **进程同步**：协调进程执行顺序，避免竞争条件
- **临界区**：访问共享资源的代码段，需要互斥访问
- **同步机制**：锁、信号量、管程等
- **经典问题**：生产者-消费者、哲学家进餐、读者-写者
- **死锁**：互相等待导致的僵局
- **死锁处理**：预防、避免、检测与解除
