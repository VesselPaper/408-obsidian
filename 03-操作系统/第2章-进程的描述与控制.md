# 第2章 进程的描述与控制

> 进程是操作系统进行资源分配和调度的基本单位，是"正在运行的程序"。本章是操作系统的核心章节！

## 2.1 从程序到进程
#第2章-进程的描述与控制/程序vs进程

### 什么是前趋图？

```
📌 简单理解：前趋图就是表示"谁先谁后"的图

示例：做饭的顺序
    煮饭 → 炒菜 → 装盘
       ↘      ↗
        准备食材

A→B 表示：A必须先完成，B才能开始
```

### 程序执行的方式

```
程序顺序执行（老式做法）：
- 一次只做一个事，CPU利用率低
- 结果确定

程序并发执行（现代做法）：
- CPU利用率高
- 结果可能不确定，需要同步机制
```

## 2.2 进程是什么？
#第2章-进程的描述与控制/进程的概念

### 进程的定义

```
📌 简单理解：进程就是"正在运行的程序"

程序：静态的文件（如微信.exe）
进程：动态的执行实体（如打开微信后）
```

### 进程的5大特征（考研必记！）

| 特征 | 说明 | 例子 |
|------|------|------|
| **动态性** | 有创建、运行、死亡的生命周期 | 进程创建→运行→终止 |
| **并发性** | 多个进程可以同时存在 | 同时打开多个软件 |
| **独立性** | 每个进程有独立资源 | 每个进程有独立内存 |
| **异步性** | 执行"走走停停" | CPU切换导致暂停 |
| **结构性** | 由程序+数据+PCB组成 | 进程控制块记录信息 |

### 进程的状态（重点！）

**三种基本状态**：
- **就绪**：准备好，等CPU分配
- **运行**：正在CPU上执行
- **阻塞**：等待某个事件（I/O等）

**状态转换**：

| 转换 | 原因 |
|------|------|
| 就绪→运行 | 被CPU选中 |
| 运行→就绪 | 时间片用完/被抢占 |
| 运行→阻塞 | 等待事件（I/O） |
| 阻塞→就绪 | 事件发生（I/O完成） |



```mermaid
stateDiagram-v2
    [*] --> 就绪 : 创建进程
    就绪 --> 运行 : 被调度选中
    运行 --> 就绪 : 时间片用完/被抢占
    运行 --> 阻塞 : 等待I/O/资源
    阻塞 --> 就绪 : I/O完成/资源得到
    运行 --> [*] : 进程终止
    note right of 运行 : 单核同一时刻只能一个进程运行
end note
```

**Linux特有状态**：
| 状态 | 含义 |
|------|------|
| **TASK_RUNNING** | 就绪或运行 |
| **TASK_INTERRUPTIBLE** | 可中断睡眠（阻塞） |
| **TASK_UNINTERRUPTIBLE** | 不可中断睡眠 |
| **TASK_STOPPED** | 暂停 |
| **TASK_ZOMBIE** | 僵尸（进程已终止但PCB未回收） |

> [!tip] 状态转换记忆
> - 运行→就绪：时间片用完或高优先级抢占（被动让出CPU）
> - 运行→阻塞：等待资源（主动让出CPU）
> - 阻塞→就绪：资源得到（不能直接进入运行！）

### 进程控制块（PCB）

```
📌 PCB就是进程的"身份证"

PCB包含的信息：

| 信息类型 | 说明 |
|----------|------|
| 进程标识符（PID） | 身份证号 |
| 进程状态 | 就绪/运行/阻塞 |
| CPU寄存器（PC等） | 暂停时保存现场 |
| 内存管理信息 | 段表/页表等 |
| 设备管理信息 | 占用的设备 |
| 文件管理信息 | 打开的文件 |
| 调度信息 | 优先级等 |
```

## 2.3 进程控制
#第2章-进程的描述与控制/进程控制

### 进程控制原语 ⭐

**原语（Primitive）**：若干条指令组成的不可分割的操作（原子操作）。

| 操作 | 功能 |
|------|------|
| **创建** | 分配PID → 分配内存 → 初始化PCB → 加入就绪队列 |
| **终止** | 释放资源 → 从队列移除 → 回收PCB |
| **阻塞** | 进程自己主动让出CPU，进入阻塞队列 |
| **唤醒** | 把阻塞队列中的进程移回就绪队列 |
| **挂起** | 把进程从内存调到外存 |
| **激活** | 把进程从外存调回内存 |

## 2.4 进程通信
#第2章-进程的描述与控制/进程通信

### 进程通信的4种方式

```
📌 简单理解：进程之间怎么"说话"

1. 共享内存（最快）：
   进程A和B共享一块内存，A写B读
   → 类似"留言板"

2. 消息传递（最常用）：
   A发消息给B，B收消息
   → 类似"发微信"

3. 管道（Unix特色）：
   连接两个进程的数据流
   → 类似"水管"

4. 信号（通知机制）：
   A给B发一个信号，B收到后处理
   → 类似"门铃"
```

### 经典通信问题

#### 生产者-消费者问题

```
问题：生产者生产数据，消费者消费数据
      缓冲区满，生产者等待
      缓冲区空，消费者等待

解决：用信号量同步
```

#### 读者-写者问题

```
问题：多个读者可同时读
      写者需要独占
      读者和写者不能同时

解决：用读写锁
```

## 2.5 线程（重要！）
#第2章-进程的描述与控制/线程

### 什么是线程？

```
📌 简单理解：线程是"轻量级进程"

进程vs线程：
进程 = 独立的公司
线程 = 公司里的员工

一个公司（进程）可以有很多员工（线程）
但员工共享公司的资源（内存、文件）
```

### 进程 vs 线程

| 对比项 | 进程 | 线程 |
|--------|------|------|
| **资源分配** | 独立分配 | 共享进程资源 |
| **CPU调度** | 不是调度单位 | 是调度单位 |
| **切换开销** | 大（要切换内存） | 小（只保存寄存器和栈） |
| **通信** | 复杂（用IPC） | 简单（直接共享） |
| **独立性** | 高 | 低 |

### 线程的实现

| 类型 | 特点 | 例子 |
|------|------|------|
| **用户级线程** | 线程库管理，内核看不到 | 早期Java线程 |
| **内核级线程** | 内核管理，CPU直接调度 | Linux线程 |
| **混合级线程** | 结合两者优点 | Windows |

## 习题2（考研真题精选）

### 选择题

1. **【2011统考真题】** 下列选项中，导致进程从运行态变为就绪态的事件是？
   A. I/O操作结束  B. 进程完成I/O  C. 时间片用完  D. 等待某事件  
   > **答案**：C  
   > **解析**：A是阻塞→就绪，B是运行→终止，C是运行→就绪，D是运行→阻塞。

2. **【2013统考真题】** 下列关于进程和线程的叙述中，正确的是？
   A. 线程是资源分配的基本单位  
   B. 线程是CPU调度的基本单位  
   C. 用户级线程可以在多核CPU上并行运行  
   D. 进程切换比线程切换开销大  
   > **答案**：B、D  
   > **解析**：进程是资源分配单位，线程是CPU调度单位，用户级线程需要映射到内核级线程才能并行。

3. **【2015统考真题】** 进程P0和P1共享一个变量x，进程P2和P3共享另一个变量y。以下关于x和y的叙述，正确的是？
   A. x和y都是临界资源  
   B. x和y都是临界区  
   C. x是临界资源，y不是  
   D. y是临界资源，x不是  
   > **答案**：A  
   > **解析**：临界资源是共享资源，临界区是访问临界资源的代码段。

4. **【2017统考真题】** 下列选项中，fork()系统调用用于创建进程，关于fork()的返回值说法正确的是？
   A. 父进程中返回子进程PID  
   B. 子进程中返回父进程PID  
   C. 父进程中返回0  
   D. 子进程中返回0  
   > **答案**：D  
   > **解析**：fork()在父进程中返回子进程PID，在子进程中返回0。

5. **【2019统考真题】** 下列选项中，不属于进程控制块组成内容的是？
   A. 程序计数器  B. 进程标识符  C. 内存管理信息  D. 库函数代码  
   > **答案**：D  
   > **解析**：PCB不包括代码本身，代码在程序段中。

### 综合应用题

6. **【2012统考真题】** 某进程的活动记录如下，请给出进程状态转换的原因。

```
状态转换序列：运行→就绪→运行→阻塞→就绪
```

**参考答案**：
```
运行→就绪：时间片用完，或被更高优先级进程抢占
就绪→运行：被进程调度程序选中
运行→阻塞：等待某事件发生（如I/O操作）
阻塞→就绪：等待的事件已发生（如I/O完成）
```

7. **【2016统考真题】** 线程相比进程有什么优点？为什么？

**参考答案**：
```
线程的优点：
1. 切换开销小：不需要切换页表等资源
2. 通信方便：共享进程的地址空间
3. 并发度高：多个线程可同时运行

原因：
- 线程共享进程的地址空间、资源
- 线程切换只需要保存少量寄存器
- 进程切换需要切换整个地址空间
```
